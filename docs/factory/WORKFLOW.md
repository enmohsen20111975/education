## 1. مقدمة

### 1.1 نظرة عامة على المنظومة

منظومة **SmartEdu Data Factory** هي المحرك الأساسي الذي يحوّل الكتب المدرسية المصرية (PDF) إلى محتوى تعليمي رقمي تفاعلي ومنظّم. المنظومة تتكون من أربعة مكونات رئيسية تعمل معًا بشكل متكامل:

| المكون | المنفذ (Port) | التقنية | الوظيفة |
|--------|--------------|----------|---------|
| **Student Platform** | `4000` | Next.js 15 | عرض المحتوى على الطلاب |
| **Factory Backend** | `3001` | Express.js | معالجة البيانات والتوليد |
| **Factory Dashboard** | `3002` | Next.js 15 | واجهة إدارة المصنع |
| **AI Services** | `1234` / `11434` | LM Studio / Ollama | خدمات الذكاء الاصطناعي |

### 1.2 المخرجات الرئيسية للمنظومة

المنظومة تنتج الأنواع التالية من المحتوى:

| نوع المحتوى | الوصف | الأدوات المستخدمة |
|-------------|-------|-------------------|
| المحتوى النصي | مفاهيم، قوانين، أمثلة، أسئلة، أهداف | LM Studio, Ollama |
| الخرائط الذهنية | عُقَد وعلاقات بصريّة | Canvas API, SVG |
| الإنفوجرافيك | معلومات بصرية مُصمَّمة | SVG, CSS |
| المخططات البيانية | بيانات رسومية متعددة الأنواع | Chart.js, D3.js |
| المحاكيات التفاعلية | تجارب ومحاكيات علمية | React, Framer Motion |
| الفيديوهات التعليمية | شرح مرئي مع صوت | Remotion, TTS |

## 3. سير عمل معالجة PDF

### 3.1 نظرة عامة

سير عمل معالجة PDF هو الخطوة الأولى في المنظومة. يحوّل ملفات PDF الممسوحة أو النصية إلى بيانات منظّمة قابلة للمعالجة بواسطة خدمات الذكاء الاصطناعي.

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│  رفع PDF  │──▶│ تخزين     │──▶│ تقسيم     │──▶│ استخراج   │──▶│ تحليل     │
│  Upload   │   │ Store    │   │ Split    │   │ Extract  │   │ Analyze  │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
                                                                   │
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐          │
│  تخزين    │◀──│ التحقق   │◀──│ هيكلة    │◀──│ كشف      │◀─────────┘
│  Store    │   │ Validate │   │ Structure│   │ Detect   │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
```

### 3.2 المرحلة 1: رفع الملف (Upload)

**المدخلات:**
- ملف PDF (الكتاب المدرسي)
- معلومات وصفية: المادة، الصف الدراسي، الفصل الدراسي

**الخطوات:**

```
Step 1: استقبال الملف
  ├── التحقق من نوع الملف (PDF فقط)
  │   ├── ✅ صحيح → تابع
  │   └── ❌ خطأ → أرجع HTTP 415 Unsupported Media Type
  │
  ├── التحقق من حجم الملف (الحد الأقصى: 200 ميجابايت)
  │   ├── ✅ ضمن الحد → تابع
  │   └── ❌ أكبر من الحد → أرجع HTTP 413 Payload Too Large
  │
  ├── التحقق من صلاحية المستخدم (Dashboard Admin)
  │   ├── ✅ مصرح → تابع
  │   └── ❌ غير مصرح → أرجع HTTP 403 Forbidden
  │
  └── توليد UUID للملف
```

```
Step 2: تخزين الملف
  ├── أنشئ مجلد مؤقت: /tmp/pdf-processing/{uuid}/
  ├── احفظ الملف الأصلي: original.pdf
  ├── سجّل البيانات الوصفية في قاعدة البيانات:
  │   {
  │     id: UUID,
  │     fileName: string,
  │     fileSize: number,
  │     subject: string,
  │     year: string,
  │     term: string,
  │     status: 'uploaded',
  │     uploadedAt: DateTime,
  │     totalPages: number
  │   }
  └── أرجع Job ID للتتبع
```

### 3.3 المرحلة 2: تقسيم الصفحات (Page Splitting)

**الأداة المستخدمة:** `pdf-lib` أو `pdfjs-dist`

```
Step 3: تقسيم الملف إلى صفحات منفصلة
  ├── افتح الملف باستخدام PDF library
  ├── استخرج عدد الصفحات الكلي
  │   ├── صفحة واحدة → معالجة مباشرة
  │   └── صفحات متعددة → استخرج كل صفحة
  │
  ├── لكل صفحة:
  │   ├── احفظ كملف منفصل: page-{N}.pdf
  │   ├── سجّل معلومات الصفحة:
  │   │   {
  │   │     pageId: UUID,
  │   │     parentJobId: Job UUID,
  │   │     pageNumber: N,
  │   │     filePath: string,
  │   │     width: number,    (نقاط)
  │   │     height: number,   (نقاط)
  │   │     status: 'pending'
  │   │   }
  │   └── حدّث حالة المهمة: status = 'splitting'
  │
  └── تحقق من اكتمال التقسيم
      ├── ✅ نجح → تابع للمرحلة التالية
      └── ❌ فشل (ملف تالف) → أرجع خطأ → أوقف المعالجة
```

### 3.4 المرحلة 3: استخراج المحتوى (Content Extraction)

هذه المرحلة هي الأكثر تعقيدًا وتتضمن عدة مسارات حسب نوع الصفحة.

```
Step 4: تحديد نوع كل صفحة
  ┌──────────────────────────────────────┐
  │     هل الصفحة تحتوي على نص قابل     │
  │       للنسخ (Text-based)?             │
  └──────────┬──Yes────────┬──No────────┘
             │              │
      ┌──────▼──────┐  ┌───▼───────────┐
      │ مسار نصي     │  │ مسار ممسوح    │
      │ Text Path    │  │ Scan Path     │
      └──────┬──────┘  └───┬───────────┘
             │              │
        Extract Text    Run OCR
             │              │
             └──────┬──────┘
                    │
                    ▼
```

**مسار النص (Text-based Page):**

```
Step 4a: استخراج النص
  ├── استخدم pdfjs-dist لاستخراج النصوص
  ├── احتفظ بترتيب النص حسب الموقع (x, y coordinates)
  ├── اكتشف اتجاه النص (RTL للعربية)
  │   ├── عربي → اضبط المعالجة لـ RTL
  │   └── إنجليزي → اضبط المعالجة لـ LTR
  │
  ├── نظّم النص في بنية هرمية:
  │   ├── headings (حسب حجم الخط)
  │   ├── paragraphs (نص عادي)
  │   ├── list items (نقاط)
  │   └── page numbers (أرقام الصفحات)
  │
  └── أنشئ تمثيل PDF-to-Text mapping
      (لتمكين الربط بين النص والصفحة الأصلية)
```

**مسار الممسوح (Scanned Page):**

```
Step 4b: معالجة OCR
  ├── حوّل الصفحة إلى صورة عالية الدقة (300 DPI)
  │   ├── PNG format
  │   └── Color space: Grayscale (للنص) أو RGB (للرسوم)
  │
  ├── استخدم Tesseract OCR مع اللغة العربية:
  │   ├── tesseract image.png output -l ara+eng
  │   ├── precision:精确模式
  │   └── confidence threshold: 70%
  │
  ├── تحقق من دقة النتيجة:
  │   ├── confidence >= 80% → اقبض النص
  │   ├── confidence 50-80% → راجع يدويًا
  │   └── confidence < 50% → أعد المعالجة أو أبلغ عن خطأ
  │
  └── استخراج النص مع إحداثيات الكلمات
```

### 3.5 المرحلة 4: كشف العناصر (Element Detection)

```
Step 5: كشف واستخراج العناصر المختلفة

  ┌─────────────────────────────────────────────────────────┐
  │                 تحليل محتوى الصفحة                       │
  │                  Page Analysis                           │
  └─────────────┬────────────┬────────────┬────────────────┘
                │            │            │
        ┌───────▼──┐  ┌─────▼────┐  ┌────▼──────┐
        │  صور     │  │  جداول   │  │  معادلات   │
        │ Images   │  │ Tables   │  │  Formulas │
        └──────┬──┘  └─────┬────┘  └────┬──────┘
                │            │            │
                ▼            ▼            ▼
```

**كشف الصور (Image Detection):**

```
Step 5a: استخراج الصور
  ├── ابحث عن كائنات الصور في PDF
  ├── لكل صورة:
  │   ├── استخرج بيانات الصورة (JPEG/PNG/SVG)
  │   ├── حدد أبعاد الصورة
  │   ├── حدد الموقع على الصفحة (x, y)
  │   ├── احفظ الصورة: images/{uuid}.png
  │   ├── توليد caption بالذكاء الاصطناعي:
  │   │   ├── Model: Qwen2.5 7B (via LM Studio)
  │   │   └── Prompt: "صِف هذه الصورة التعليمية بالعربية والإنجليزية"
  │   └── سجّل البيانات:
  │       {
  │         id: UUID,
  │         type: 'image',
  │         filePath: string,
  │         captionAr: string,
  │         captionEn: string,
  │         width: number,
  │         height: number,
  │         pageNumber: N
  │       }
  │
  ├── تصنيف الصور:
  │   ├── صور توضيحية (diagrams)
  │   ├── صور فوتوغرافية (photos)
  │   ├── رسوم بيانية (charts)
  │   └── خرائط (maps)
  │
  └── تحقق: هل الصورة منخفضة الجودة؟
      ├── ✅ جودة مقبولة → حفظ
      └── ❌ جودة منخفضة → حاول تحسينها أو علامة للاستبدال
```

**كشف الجداول (Table Detection):**

```
Step 5b: استخراج الجداول
  ├── اكتشف حدود الجداول (Table Borders)
  │   ├── تحليل الخطوط الأفقية والرأسية
  │   └── تحديد خلايا الجدول
  │
  ├── لكل جدول:
  │   ├── استخرج الصفوف والأعمدة
  │   ├── حدد الخلايا المدمجة (merged cells)
  │   ├── استخرج النص من كل خلية
  │   ├── حدد ترتيب القراءة (RTL)
  │   └── سجّل البيانات:
  │       {
  │         id: UUID,
  │         type: 'table',
  │         rows: number,
  │         cols: number,
  │         data: [{ row: N, col: M, text: string }],
  │         hasHeader: boolean,
  │         pageNumber: N
  │       }
  │
  └── تحقق من اكتمال البيانات
      ├── ✅ البيانات مكتملة → حفظ
      └── ❌ خلايا فارغة → أرجع تنبيه → استمر
```

**كشف المعادلات (Formula Detection):**

```
Step 5c: استخراج المعادلات والصيغ الرياضية
  ├── اكتشف أنماط المعادلات:
  │   ├── نص بلغة LaTeX (إذا كان موجودًا في PDF)
  │   ├── رموز رياضية خاصة (∫, ∑, √, π, α, β, etc.)
  │   ├── أرقام مرتفعة ومنخفضة (superscript/subscript)
  │   └── خطوط كسور (fraction bars)
  │
  ├── لكل معادلة:
  │   ├── استخرج النص الخام
  │   ├── حوّل إلى LaTeX:
  │   │   ├── استخدم نموذج AI لتحويل النص إلى LaTeX
  │   │   ├── Model: DeepSeek-Coder V2:16B (via Ollama)
  │   │   └── تحقق من صحة LaTeX
  │   ├── استخرج شرح المعادلة (إذا وُجد)
  │   └── سجّل البيانات:
  │       {
  │         id: UUID,
  │         type: 'formula',
  │         latex: string,
  │         rawText: string,
  │         explanation: string,
  │         pageNumber: N
  │       }
  │
  └── أنشئ MathML كنسخة احتياطية (fallback)
```

**كشف الأسئلة (Question Detection):**

```
Step 5d: كشف أسئلة الكتاب المدرسي
  ├── ابحث عن أنماط الأسئلة:
  │   ├── "اختار الإجابة الصحيحة" / "Choose the correct answer" → MCQ
  │   ├── "صح أم خطأ" / "True or False" → True/False
  │   ├── "ماذا نعني بـ" / "What do we mean by" → Short Answer
  │   ├── أرقام مرقمة (1, 2, 3...) → أسئلة مرقمة
  │   └── علامات الاستفهام (؟ / ?) → أسئلة مباشرة
  │
  ├── لكل سؤال:
  │   ├── حدد النوع (MCQ / T-F / SA)
  │   ├── استخرج السؤال
  │   ├── استخرج الخيارات (لـ MCQ)
  │   ├── استخرج الإجابة النموذجية (إن وُجدت)
  │   └── سجّل:
  │       {
  │         id: UUID,
  │         type: 'mcq' | 'trueFalse' | 'shortAnswer',
  │         questionText: string,
  │         options: string[] | null,
  │         answer: string | null,
  │         pageNumber: N
  │       }
  │
  └── مراجعة يدوية مُوصى بها (بخاصة للأسئلة المعقدة)
```

### 3.6 المرحلة 5: هيكلة المحتوى (Structuring)

```
Step 6: تجميع المحتوى في هيكل تعليمي
  ├── حدد حدود الوحدات والدروس:
  │   ├── ابحث عن عناوين الفصول (Chapter headings)
  │   ├── ابحث عن عناوين الوحدات (Unit headings)
  │   ├── ابحث عن عناوين الدروس (Lesson headings)

  │
  ├── اربط المحتوى بالهيكل:
  │   لكل درس:
  │   ├── مقدمة الدرس (من النص الأول)

  │   ├── الأمثلة (من "مثال:" / "Example:")

  │   └── الصور والرسوم التوضيحية
  │
  ├── أنشئ JSON للدرس:

  │       questions: [...]

  │

      └── quality score (0-100)
```

### 3.7 المرحلة 6: التحقق والمعالجة اليدوية (Validation)

```
  ├── تقرير الجودة:

  │     jobId: UUID,
```

## 4. سير عمل توليد المحتوى النصي

### 4.1 نظرة عامة

سير عمل توليد المحتوى النصي يستخدم نماذج الذكاء الاصطناعي لإنشاء محتوى تعليمي ثنائي اللغة (عربي/إنجليزي) لكل درس من الكتب المدرسية.

```
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│ اختر الدرس     │────▶│ اختر نوع      │────▶│ اختر الموديل   │
│ Select Lesson │     │ Content Type  │     │ AI Model      │
└───────────────┘     └───────────────┘     └───────┬───────┘
                                                      │
┌───────────────┐     ┌───────────────┐     ┌───────▼───────┐
│ تخلّص من       │◀────│ خزّن في DB     │◀────│ ولّد المحتوى   │
│ الرد غير الصالح│     │ Store in DB   │     │ Generate       │
└───────────────┘     └───────────────┘     └───────────────┘
```

### 4.2 أنواع المحتوى النصي

| نوع المحتوى | الرمز في النظام | الوصف |
|-------------|----------------|-------|
| المفاهيم والتعريفات | `Concept` | مصطلحات وتعريفات علمية |
| القوانين والصيغ | `Formula` | معادلات رياضية/فيزيائية مع شرح |
| الأمثلة المحلولة | `Example` | مسائل مع حل خطوة بخطوة |
| أسئلة MCQ | `Question (mcq)` | اختيار من متعدد |
| أسئلة صح/خطأ | `Question (trueFalse)` | True or False |
| أسئلة إجابة قصيرة | `Question (shortAnswer)` | إجابة قصيرة |
| أهداف الدرس | `Objective` | ما سيتعلمه الطالب |
| مقدمة الدرس | `Lesson.introduction` | تمهيد للدرس |
| ملخص الدرس | `Lesson.summary` | خلاصة المفاهيم الرئيسية |

### 4.5 معالجة الاستجابة من الذكاء الاصطناعي

```
Step: معالجة رد الـ AI

  1. استقبل النص الخام من الـ API
     ├── HTTP Response (200 OK)
     └── Body: string (text/plain)

  2. استخرج JSON من النص
     ├── ابحث عن { و }
     ├── أزل النصوص قبل JSON وبعده
     ├── ابحث عن ```json ... ```
     └── JSON.parse()

  3. التحقق من صحة JSON
     ├── ✅ JSON صالح → تابع
     └── ❌ JSON غير صالح →
         ├── حاول إصلاح JSON (JSON repair)
         ├── أعد الطلب مع prompt أوضح
         └── بعد 3 محاولات → استخدم fallback model

  4. التحقق من الحقول المطلوبة
     ├── هل كل الحقل required موجودة؟
     ├── هل القيم ليست فارغة؟
     ├── هل القيم ضمن النطاق المتوقع؟
     └── هل اللغة العربية صحيحة (UTF-8)?

  5. تنظيف المحتوى
     ├── أزل الأحرف غير المسموحة
     ├── تطبيع Unicode (Arabic normalization)
     ├── تحويل HTML entities
     └── تقليم الفراغات الزائدة

  6. حفظ في قاعدة البيانات (Prisma)
     └── await prisma.model.create({ data: cleanedData })
```

```
  ├── الميزات التفاعلية:
  │   ├── تكبير وتصغير (zoom/pan)
  │   ├── توسيع/طي العقد (expand/collapse)
  │   ├── سحب العقد (drag & drop)
  │   ├── تحديد العقد (selection)
  │   └── RTL support
  │
  └── التصدير: PNG / SVG

Step 4: التخزين
  ├── احفظ JSON في جدول MindMap:
  │   {
  │     id: UUID,
  │     lessonId: string (unique),
  │     data: JSON.stringify(mindMapData)
  │   }
  └── أرسل إشعار sync
```

### 6.2 المرحلة 1: كتابة السكريبت (Script Generation)

```
Step 1: تحليل محتوى الدرس
  ├── حمّل: مقدمة، مفاهيم، قوانين، أمثلة
  ├── حدد النقاط الرئيسية
  └── حدد مدة الفيديو المطلوبة (3-8 دقائق)

Step 2: توليد السكريبت بالذكاء الاصطناعي
  ├── النموذج: Scaled Oss 36B (أفضل للنصوص الطويلة والمنطقية)
  ├── البديل: Qwen2.5 7B
  │
  ├── Prompt:
  │   """
  │   أنشئ سكريبت فيديو تعليمي لهذا الدرس.
  │   المادة: {subject}
  │   الدرس: {lessonTitle}
  │   المدة المطلوبة: {duration} دقائق
  │
  │   السكريبت يجب أن يحتوي على:
  │   1. مقدمة جذابة (Hook) - 20 ثانية
  │   2. شرح المفاهيم الرئيسية
  │   3. أمثلة توضيحية
  │   4. ملخص سريع
  │
  │   لكل مقطع حدّد:
  │   - النص المطلوب نطقه (voiceover)
  │   - نوع المرئيات المطلوبة (diagram, animation, text)
  │   - المدة التقريبية
  │   """
  │
  └── المخرجات:
      {
        "sections": [
          {
            "id": "s1",
            "type": "intro",
            "voiceover": "...",
            "visual": "animated_text",
            "duration": 20,
            "order": 1
          }
        ],
        "totalDuration": 300,
        "language": "ar"
      }

Step 3: مراجعة السكريبت
  ├── هل المدة مناسبة؟
  ├── هل المحتوى تعليمي ودقيق؟
  ├── هل المرئيات قابلة للتوليد؟
  └── هل النص مناسب للنطق؟ (pronunciation check)
```

### 6.3 المرحلة 2: توليد الصوت (TTS - Text to Speech)

```
Step 4: تحويل النص إلى صوت
  ├── خيارات TTS:
  │   ├── خيار 1: AI TTS (عبر LM Studio أو خدمة خارجية)
  │   │   ├── Model: Arabic TTS model
  │   │   ├── Voice: male/female option
  │   │   ├── Speed: 0.9x - 1.2x
  │   │   └── Output: WAV/MP3
  │   │
  │   ├── خيار 2: Local TTS engine
  │   │   ├── pyttsx3 / espeak
  │   │   └── جودة أقل لكن بدون إنترنت
  │   │
  │   └── خيار 3: Pre-recorded (للمحتوى المهم)
  │       ├── تسجيل صوت بشري احترافي
  │       └── أعلى جودة
  │
  ├── لكل مقطع في السكريبت:
  │   ├── ولّد ملف صوتي: audio_{sectionId}.mp3
  │   ├── تحقق من المدة الفعلية
  │   └── قارن مع المدة المتوقعة (±10%)
  │
  └── إعادة التوليد إذا:
      ├── المدة غير مناسبة
      ├── جودة الصوت غير كافية
```

## 7. سير عمل المزامنة ثنائية الاتجاه

### 7.1 نظرة عامة

نظام المزامنة يضمن أن البيانات متطابقة بين Factory Backend و Student Platform في كلا الاتجاهين.

```
┌──────────────────┐              ┌──────────────────┐
│   Factory         │              │   Student         │
│   Backend         │◄────────────►│   Platform        │
│   (:3001)         │   Sync API   │   (:4000)         │
│                   │              │                   │
│  - Generate       │              │  - Display        │
│  - Process       │              │  - Student Edits  │
│  - Dashboard Ctrl │              │  - User Data      │
└────────┬──────────┘              └────────┬──────────┘
         │                                  │
         │         ┌──────────┐             │
         └────────►│  SQLite  │◄────────────┘
                   │ Database │
                   └──────────┘
```

### 7.2 اتجاه Factory → Platform

```
Step 1: حدث في Factory
  ├── نوع الأحداث:
  │   ├── "content_created" ← محتوى جديد تم توليده
  │   ├── "content_updated" ← محتوى تم تعديله
  │   ├── "content_deleted" ← محتوى تم حذفه
  │   ├── "visual_generated" ← محتوى بصري جديد
  │   ├── "video_ready" ← فيديو جاهز
  │   └── "batch_completed" ← عملية مجمّعة انتهت
  │
  └── أنشئ Sync Event:
      {
        eventId: UUID,
        type: 'content_updated',
        entityType: 'Lesson' | 'Concept' | 'Formula' | ...,
        entityId: string,
        changes: { field: newValue },
        timestamp: DateTime,
        source: 'factory'
      }

Step 2: أرسل إشعار للمنصة
  ├── HTTP POST: http://localhost:4000/api/sync/webhook
  ├── أو WebSocket (real-time)
  ├── أو Polling (fallback): GET /api/sync/changes?since={timestamp}
  │
  └── إعادة المحاولة:
      ├── 3 محاولات مع exponential backoff
      ├── delay: 1s → 2s → 4s
      └── بعد 3 فشلات → سجّل في sync_queue للمعالجة لاحقًا

Step 3: المنصة تتلقى الإشعار
  ├── تحقق من صلاحية المصدر (source verification)
  ├── طبّق التغييرات على الـ Cache المحلي
  ├── حدّث UI (إذا كان المستخدم يعرض الصفحة)
  │   └── Server-Sent Events (SSE) أو WebSocket
  └── أرسل تأكيد الاستلام (ACK)
```

### 7.3 اتجاه Platform → Factory

```
Step 1: تعديل من المنصة
  ├── أنواع التعديلات المسموحة:
  │   ├── تعديل نص المقدمة
  │   ├── تعديل شرح مفهوم
  │   ├── تصحيح سؤال
  │   ├── إضافة مثال جديد
  │   └── تعديل ترجمة
  │
  ├── أنواع التعديلات غير المسموحة (فقط Factory):
  │   ├── حذف درس كامل
  │   ├── تغيير هيكل المنهج
  │   └── تعديل بيانات الـ AI generation
  │
  └── أنشئ Edit Event:
      {
        eventId: UUID,
        type: 'manual_edit',
        entityType: 'Concept',
        entityId: string,
        changes: { definitionAr: "new text" },
        editedBy: userId,
        timestamp: DateTime,
        source: 'platform'
      }

Step 2: أرسل للـ Factory
  ├── HTTP POST: http://localhost:3001/api/sync/receive
  ├── تحقق من صلاحية المُعدّل
  └── طبّق التغييرات في Factory DB

Step 3: Factory يعالج التعديل
  ├── هل التعديل يتعارض مع محتوى مولّد؟
  │   ├── لا تعارض → احفظ التعديل
  │   └── يوجد تعارض →
  │       ├── علّم بـ "manually_edited"
  │       ├── لا تُعد توليد المحتوى تلقائيًا
  │       └── أبلغ المشرف في Dashboard
  │
  └── أرسل تأكيد للمنصة
```

### 7.4 آلية حل التعارضات (Conflict Resolution)

```
┌──────────────────────────────────────────────────────────────┐
│                 Conflict Resolution Strategy                    │
├──────────────────────────────────────────────────────────────┤
│                                                                │
│  Rule 1: "Last Write Wins" (للحقول البسيطة)                    │
│    ← التعديل الأحدث يفوز                                       │
│                                                                │
│  Rule 2: "Factory Takes Priority" (للمحتوى المولّد)             │
│    ← إذا Factory أعاد توليد المحتوى                             │
│    ← يُحفظ بإصدار جديد ويُحفظ التعديل اليدوي كإصدار سابق       │
│                                                                │
│  Rule 3: "Manual Edit Protected" (للتعديلات اليدوية)            │
│    ← التعديلات اليدوية تُعلّم بـ "manually_edited: true"         │
│    ← لا تُستبدل بتوليد تلقائي                                   │
│    ← يمكن للمشرف إزالة الحماية يدويًا                          │
│                                                                │
│  Rule 4: "User Data Isolation"                                 │
│    ← بيانات المستخدم (progress, scores) لا تتأثر بالمزامنة       │
│    ← كل مستخدم له بياناته المستقلة                              │
│                                                                │
└──────────────────────────────────────────────────────────────┘
```

### 7.5 جدول المزامنة (Sync Table Schema)

```typescript
interface SyncEvent {
  id: string;
  type: 'content_created' | 'content_updated' | 'content_deleted' | 'manual_edit';
  entityType: 'Lesson' | 'Concept' | 'Formula' | 'Example' | 'Question' | 'Objective';
  entityId: string;
  changes: Record<string, any>;
  source: 'factory' | 'platform';
  timestamp: DateTime;
  acknowledged: boolean;
  retryCount: number;
}
```

## 8. سير العمل المجمّع (Batch Processing)

### 8.1 نظرة عامة

سير العمل المجمّع يسمح بمعالجة عدة دروس دفعة واحدة، مع تتبع التقدم ومعالجة الأخطاء.

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ اختر دروس    │────▶│ أنشئ طابور    │────▶│ معالجة       │
│ متعددة       │     │ Queue        │     │ Sequential   │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                   │
┌──────────────┐     ┌──────────────┐     ┌──────▼───────┐
│ تقرير نهائي  │◀────│ اكتملت كل   │◀────│ تتبع التقدم  │
│ Final Report │     │ العناصر     │     │ Progress     │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 8.2 المرحلة 1: اختيار وتهيئة المجموعة

```
Step 1: اختيار الدروس للمعالجة المجمّعة
  ├── خيارات الاختيار:
  │   ├── كل دروس مادة معينة
  │   ├── كل دروس فصل دراسي
  │   ├── كل دروس صف دراسي كامل
  │   ├── دروس بدون محتوى فقط (missing content)
  │   └── اختيار يدوي من القائمة
  │
  ├── فلاتر إضافية:
  │   ├── نوع المحتوى: نصي / بصري / فيديو / كامل
  │   ├── الأولوية: عالية / متوسطة / منخفضة
  │   └── النموذج: محدد أو تلقائي
  │
  └── أنشئ Batch Job:
      {
        batchId: UUID,
        name: string,
        totalItems: number,
        filter: {...},
        settings: {
          contentType: 'full' | 'text' | 'visual' | 'video',
          model: 'auto' | 'qwen2.5-7b' | 'deepseek-coder-16b',
          retryOnError: boolean,
          stopOnError: boolean
        },
        createdAt: DateTime,
        status: 'pending'
      }
```

### 8.3 المرحلة 2: إنشاء الطابور (Queue)

```
Step 2: تجهيز عناصر الطابور
  ├── لكل درس في المجموعة:
  │   ├── أنشئ Queue Item:
  │   │   {
  │   │     id: UUID,
  │   │     batchId: UUID,
  │   │     lessonId: string,
  │   │     lessonTitle: string,
  │   │     subjectName: string,
  │   │     order: number,
  │   │     status: 'pending',
  │   │     attempts: 0,
  │   │     result: null,
  │   │     error: null,
  │   │     startedAt: null,
  │   │     completedAt: null
  │   │   }
  │   └── أضف للطابور مرتبًا حسب الأولوية
  │
  └── أنشئ جدول BatchProgress:
      {
        batchId: UUID,

        completed: 0,
        failed: 0,
        skipped: 0,
        inProgress: 0,

```

### 8.4 المرحلة 3: المعالجة التسلسلية

```
Step 3: معالجة العناصر واحدًا تلو الآخر
  ├── لكل عنصر في الطابور:
  │   │
  │   ├── حدّث الحالة: status = 'in_progress'
  │   ├── سجّل البدء: startedAt = now()
  │   │
  │   ├── نفّذ سير عمل توليد المحتوى (من القسم 4):
  │   │   ├── 1. تحميل بيانات الدرس
  │   │   ├── 2. توليد مقدمة وأهداف ومفاهيم (parallel)
  │   │   ├── 3. توليد قوانين وأمثلة وأسئلة (parallel)
  │   │   ├── 4. توليد ملخص
  │   │   └── 5. تخزين في DB
  │   │
  │   ├── هل نجحت المعالجة؟
  │   │   ├── ✅ نعم:
  │   │   │   ├── status = 'completed'
  │   │   │   ├── completedAt = now()
  │   │   │   ├── result = { contentIds: [...] }
  │   │   │   └── batchProgress.completed++
  │   │   │
  │   │   └── ❌ لا:
  │   │       ├── هل attempts < maxRetries (3)?
  │   │       │   ├── نعم:
  │   │       │   │   ├── attempts++
  │   │       │   │   ├── أعد العنصر للطابور (delay: 5s * attempts)
  │   │       │   │   └── سجّل: error = errorMessage
  │   │       │   │
  │   │       │   └── لا:
  │   │       │       ├── status = 'failed'
  │   │       │       ├── error = lastErrorMessage
  │   │       │       └── batchProgress.failed++
  │   │       │
  │   │       └── هل stopOnError = true?
  │   │           ├── نعم → أوقف المجموعة بالكامل
  │   │           └── لا → تابع للعنصر التالي
  │   │
  │   ├── أرسل تحديث التقدم للـ Dashboard
  │   │   └── WebSocket: { batchId, completed, total, currentLesson }
  │   │
  │   └── احسب الوقت المتبقي:
  │       └── eta = avgTime * remainingItems
  │
  └── تابع للعنصر التالي
```

### 9.2 استراتيجية إعادة المحاولة (Retry Strategy)

```
┌─────────────────────────────────────────────────────────────────┐
│                    Retry Strategy                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1st Attempt  → الفشل → انتظر 1 ثانية                           │
│  2nd Attempt  → الفشل → انتظر 2 ثانية (x2)                     │
│  3rd Attempt  → الفشل → انتظر 4 ثانية (x2)                     │
│  4th Attempt  → الفشل → انتظر 8 ثانية (x2)                     │
│  5th Attempt  → الفشل → Fallback Model                          │
│                                                                  │
│  إذا Fallback فشل أيضاً →                                        │
│    → سجّل الخطأ                                                  │
│    → حدّث حالة العنصر → 'failed'                                 │
│    → تابع للعنصر التالي (إذا batch) أو أبلغ المشرف               │
│                                                                  │
│  Exponential Backoff: delay = baseDelay * (2 ^ attempt)         │
│  Max delay: 30 ثانية                                             │
│  Jitter: ±20% عشوائي لتجنب thundering herd                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 9.3 معالجة أخطاء الذكاء الاصطناعي

```
مشكلة: JSON Parse Error
  ├── السبب: الـ AI أرجع نصًا بدلاً من JSON
  ├── المحلول:
  │   1. ابحث عن JSON في النص (extract between { and })
  │   2. أزل markdown code blocks
  │   3. استخدم JSON repair library
  │   4. أعد الطلب مع: "أرجع JSON فقط بدون أي نص إضافي"
  │   5. أعد الطلب مع: "أغلف النتيجة في <json>...</json>"
  │   └── بعد 3 محاولات → fallback model
  │
  └── الوقاية:
      ├── أضف "Return ONLY valid JSON" في System Prompt
      ├── استخدم structured output (إذا كان الموديل يدعمه)
      └── أضف JSON schema في الـ prompt

مشكلة: Hallucination (معلومات غير صحيحة)
  ├── السبب: الـ AI اخترع معلومات غير موجودة في المنهج
  ├── المحلول:
  │   1. أضف المزيد من السياق (محتوى PDF المرجعي)
  │   2. أضف: "استند فقط على المحتوى المقدم"
  │   3. استخدم نموذج أكبر وأكثر دقة
  │   4. قارن المخرجات بالمحتوى المرجعي (similarity check)
  │   └── علّم للمراجعة اليدوية
  │
  └── الوقاية:
      ├── قيّد الـ prompt بالمنهج المصري فقط
      ├── لا تستخدم general knowledge بدون سياق
      └── أضف أمثلة (few-shot prompting)

مشكلة: Timeout (انتهاء الوقت)
  ├── السبب: الموديل بطيء أو مشغول
  ├── المحلول:
  │   1. انتظر وزِد الـ timeout
  │   2. حوّل لنموذج أصغر وأسرع
  │   3. اختصر الـ prompt
  │   4. قسّم الطلب لعدة طلبات أصغر
  │   └── أعد المحاولة بعد 10 ثوانٍ
  │
  └── الوقاية:
      ├── راقب استخدام GPU
      ├── لا ترسل أكثر من طلب واحد في نفس الوقت (لنفس الموديل)
      └── استخدم queue للطلبات

مشكلة: GPU Out of Memory
  ├── السبب: الموديل كبير جدًا لذاكرة GPU المتاحة
  ├── المحلول:
  │   1. حوّل لنموذج أصغر
  │   2. قلّل max_tokens
  │   3. أغلق التطبيقات الأخرى التي تستخدم GPU
  │   4. أعد تشغيل LM Studio / Ollama
  │   └── إذا مستمر → علّم خطأ حرج
  │
  └── الوقاية:
      ├── راقب VRAM usage
      ├── لا تشغّل أكثر من موديل واحد في نفس الوقت
```


### 10.3 استراتيجية Fallback

```
┌─────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────┤

│  المحاولة الثالثة (Fallback #2 - خدمة مختلفة)                    │
│    ├── هل الخدمة الأخرى متاحة؟                                   │
│    │   ├── نعم → جرب الموديل البديل                              │
│    │   └── لا → ↓                                                │

│    └── فشل → ↓                                                   │

│  فشل نهائي (Final Failure)                                       │
│    ├── سجّل الخطأ الكامل                                        │
```
