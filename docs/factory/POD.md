## 1. نظرة عامة

### 1.1 وصف المنتج

**SmartEdu Data Factory** هو نظام إنتاج محتوى تعليمي متكامل يعمل محلياً على اللابتوب، مصمم لإنشاء وإدارة وتوليد جميع أنواع المحتوى التعليمي اللازم لمنصة **SmartEdu** — المنصة التعليمية التفاعلية للمرحلة الثانوية المصرية.

النظام يعمل كـ **مصنع بيانات** (Data Factory) يتولى دورة حياة المحتوى بالكامل: من استقبال مصادر المعرفة الخام (كتب PDF ممسوحة ضوئياً) إلى إنتاج المحتوى النهائي المنظم (نصوص، صور، صيغ رياضية، خرائط ذهنية، انفوجرافيك، محاكيات، فيديوهات تعليمية، اختبارات) وتصديره إلى المنصة الرئيسية بشكل تلقائي.

### 1.2 السياق والخلفية

منصة **SmartEdu** تخدم طلاب الثانوية العامة المصرية (15-18 سنة) عبر شعبتين:
- **الشعبة العلمية** (رياضيات + علوم)
- **الشعبة الأدبية**

المنصة مبنية بـ Next.js 15 وتحتوي حالياً على:
- **444 درس** عبر **39 مادة دراسية** في **3 سنوات**
- **111 محاكي تفاعلي** (فيزياء، كيمياء، رياضيات، أحياء)
- **23 خريطة ذهنية** تفاعلية
- **25 مخطط بياني** تعليمي
- **8,000+ سؤال** اختباري
- نظام تقدم ونقاط وشارات

المنصة الرئيسية (Student Platform) مكتملة بنسبة ~90%، لكن المحتوى حالياً يُولّد بطرق شبه يدوية عبر سكربتات منفصلة. الـ Data Factory سيتيح أتمتة هذه العملية بالكامل.

### 1.3 المشكلة التي يحلها النظام

| المشكلة الحالية | الحل المقترح |
|---|---|
| توليد المحتوى يتم بسكربتات متفرقة ويدوية | نظام موحد واحد يدير كل شيء من واجهة واحدة |
| لا توجد طريقة مركزية لرفع الكتب واستخراج المحتوى | رفع PDF → استخراج تلقائي بالـ AI → تنظيم منظم |
| لا يوجد محرر مرئي للمحتوى قبل النشر | محرر شامل مع تبويبات لكل نوع محتوى |
| الفيديوهات تُنتج بشكل يدوي لكل درس | توليد فيديو آلي بضغطة زر من المحتوى المستخرج |
| التغييرات في المنصة لا تعكس في المحتوى المصدر والعكس | مزامنة ثنائية الاتجاه في الوقت الحقيقي (Bidirectional Sync) |
| لا يوجد تحكم في موارد اللابتوب أثناء التوليد | مراقبة GPU/RAM/CPU مع حدود أمان |

### 1.4 النطاق (Scope)

**داخل النطاق (In Scope):**
- استخراج المحتوى من كتب PDF ممسوحة ضوئياً
- توليد وتحرير المحتوى النصي (عربي + إنجليزي)
- إنشاء الخرائط الذهنية والانفوجرافيك والمخططات
- توليد فيديوهات تعليمية بصوت AI
- إنشاء الأسئلة والاختبارات
- المزامنة الثنائية مع المنصة الرئيسية
- لوحة تحكم شاملة لإدارة كل شيء

**خارج النطاق (Out of Scope):**
- استضافة سحابية (النظام يعمل محلياً فقط)
- نظام دفع واشتراكات (يتم في المنصة الرئيسية)
- تطبيقات موبايل أصلية (يتم في المنصة الرئيسية)
- خدمات Tutoring أو تعليم مباشر

## 3. المستخدمون المستهدفون

### 3.1 المستخدم الأساسي: مدير المحتوى (Content Manager)

| الخاصية | الوصف |
|---|---|
| **الدور** | Product Owner + Content Supervisor |
| **المهارات التقنية** | متوسطة — يتعامل مع واجهات ويب لكن ليس مبرمج |
| **الأدوات** | لوحة تحكم الـ Dashboard (Next.js) |
| **المهام** | رفع الكتب، مراجعة المحتوى، توليد الفيديوهات، التصدير |
| **التكرار** | يومياً — 4-6 ساعات |

### 3.2 المستخدم الثانوي: مطور النظام (Developer)

| الخاصية | الوصف |
|---|---|
| **الدور** | Full Stack Developer (أو AI Agent) |
| **المهارات التقنية** | عالية — Next.js, Express, Python, Remotion |
| **الأدوات** | IDE, Terminal, API, Code Editor |
| **المهام** | تطوير وصيانة النظام، إضافة ميزات جديدة، إصلاح الأخطاء |
| **التكرار** | حسب الحاجة — أسبوعياً |

### 3.3 المستخدم الضمني: الطالب (End User)

الطالب لا يتعامل مع الـ Data Factory مباشرة لكنه المستفيد النهائي من المحتوى المنتج عبر المنصة الرئيسية. يجب مراعاة:
- المحتوى يجب أن يكون باللغة العربية الفصحى المبسطة
- الصيغ الرياضية يجب أن تكون دقيقة 100%
- الفيديوهات يجب أن تكون بصوت واضح ولهجة مصرية
- الأسئلة يجب أن تغطي مستويات صعوبة متعددة

## 5. المتطلبات غير الوظيفية

| المعرف | المتطلب | القيمة المستهدفة |
|---|---|---|

| NFR-5 | زمن حفظ الدرس | ≤ 1 ثانية |
| NFR-6 | زمن استجابة API (أي endpoint) | ≤ 500 مللي ثانية |
| NFR-7 | وقت تشغيل لوحة التحكم (Cold Start) | ≤ 5 ثوانٍ |

| المعرف | المتطلب | الحد الأقصى |
|---|---|---|
| NFR-8 | استهلاك GPU VRAM | ≤ 7 غيغابايت (من أصل 8 غيغابايت) |
| NFR-9 | استهلاك RAM | ≤ 14 غيغابايت (من أصل 32 غيغابايت) |
| NFR-10 | حرارة CPU | ≤ 90 درجة مئوية |
| NFR-11 | مساحة القرص المتاحة دائماً | ≥ 5 غيغابايت حرة |
| NFR-12 | عمليات استخراج متوازية | 1 فقط (تسلسلي) |
| NFR-13 | عمليات فيديو متوازية | 1 فقط (تسلسلي) |

### 5.3 الموثوقية (Reliability)

| المعرف | المتطلب | الوصف |

| **التخزين** | SSD | (غير محدد بالضبط — يُفترض ≥ 512 غيغابايت) |

**توزيع الأحمال المقترح:**
- **GPU 0 (RTX 4000)**: استدلال نماذج AI (VLM, LLM), Render بـ Remotion
- **GPU 1 (UHD)**: عرض واجهة المستخدم فقط
- **CPU**: تشغيل Backend (Express), Python scripts, FFmpeg
- **RAM**: توزيع: ~8GB للنماذج، ~8GB لـ Remotion، ~8GB للنظام، ~8GB احتياطي

### 6.2 نماذج الذكاء الاصطناعي المحلية (AI Models)

#### 6.2.1 LM Studio (HTTP API على `localhost:1234`)

| النموذج | الحجم | السرعة | الاستخدام المقترح |
|---|---|---|---|
| **Qwen3 1.7B** | ~1.7 مليار معامل | سريع جداً (~100 token/sec) | مهام خفيفة: تصنيف، توليد عناوين، تنظيم |

**ملاحظة**: Qwen2.5 7B هو النموذج الأساسي لمعظم المهام. يوازن بين السرعة والجودة.


### 10.2 بروتوكولات الأمان لموارد اللابتوب

#### قواعد الاستدلال (Inference Rules)

| القاعدة | القيمة | التفسير |
|---|---|---|
| **VRAM Limit** | 7 GB (من 8 GB) | إيقاف الاستدلال إذا تجاوز الحد |
| **RAM Limit** | 14 GB (من 32 GB) | إيقاف العمليات إذا تجاوز الحد |
| **Cooldown بين الصفحات** | 10 ثوانٍ | حماية GPU من السخونة |
| **GPU Check Retries** | 3 محاولات | قبل الإبلاغ عن فشل |
| **GPU Retry Wait** | 30 ثانية | انتظار بين المحاولات |
| **التوازي الأقصى** | 1 عملية ثقيلة | تسلسلي فقط (استخراج أو فيديو) |
| **Temperature (استخراج)** | 0.1 | دقة عالية — أقل إبداع |
| **Temperature (محتوى)** | 0.3 | توازن بين الدقة والإبداع |
| **Max Tokens** | 4096 | لكل استدلال واحد |

#### Red Flags — إيقاف فوري

| المؤشر | الحد | الإجراء |
|---|---|---|
| GPU VRAM | > 7.5 GB | إيقاف فوري للاستدلال |
| RAM | > 14 GB | إيقاف العمليات الثقيلة |
| CPU Temp | > 90°C | إيقاف + انتظار تبريد |
| Disk Free | < 5 GB | تنبيه + إيقاف توليد فيديو |
| فشل متتالي | 3 صفحات | توقف + تنبيه المستخدم |

### 11.2 نقاط التكامل (Integration Points)

#### 11.2.1 قاعدة البيانات المشتركة

- **الآلية**: كلا المشروعين يشيران لنفس ملف SQLite (`db/custom.db`)
- **التحديث من Factory**: عند حفظ درس → `prisma.lesson.update()` + تحديث الجداول الفرعية
- **التحديث من Platform**: عند تعديل محتوى في المنصة → يُقرأ في Factory في المرة القادمة
- **التحدي**: يجب عدم وجود تعارض (Concurrency) — حل: عملية واحدة في كل لحظة

#### 11.2.2 تصدير JSON

- الـ Factory يُنتج `education-export.json` بصيغة متوافقة مع `prisma/seed.ts`
- المنصة تستطيع استيراد هذا الملف لتحديث البيانات
- الصيغة تتضمن: lessons, concepts, formulas, examples, objectives, questions

#### 11.2.3 رابط الفيديو

- عند توليد فيديو → تحديث حقل `Lesson.videoUrl` في SQLite
- المنصة تقرأ `videoUrl` وتعرض مشغل الفيديو في صفحة الدرس
- الرابط يمكن أن يكون: مسار محلي أو Cloudflare R2 URL
