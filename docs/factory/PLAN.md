## 1. الملخص التنفيذي

### 1.1 الهدف

بناء **مصنع بيانات تعليمي متكامل** (Data Factory) يعمل بالكامل على لابتوب محلي، يقوم بـ:

1. **استخراج المحتوى** من كتب PDF المدرسية المصرية (الثانوية العامة) عبر OCR محلي
2. **توليد المحتوى النصي** تعليمي ثنائي اللغة (عربي/إنجليزي) باستخدام نماذج AI محلية
3. **توليد المحتوى المرئي** (خرائط ذهنية، إنفوجرافيك، رسوم بيانية متحركة، صور تعليمية)
4. **إنتاج فيديوهات تعليمية** احترافية مع تعليق صوتي عربي
5. **مزامنة ثنائية الاتجاه** مع منصة الطالب (Student Platform) لتحديث المحتوى فوراً

### 1.2 الحالة الراهنة

| المكوّن | نسبة الإنجاز | التقنية | ملاحظات |
|---------|-------------|---------|---------|
| Student Platform | 90% | Next.js 15 + Prisma + SQLite | يعمل على port 4000 |
| Factory Dashboard | 80% | Next.js 15 (منفصل) | في `mini-services/control-center/dashboard-app` |
| Factory Backend | 75% | Express + Socket.io | في `mini-services/control-center/dashboard-server.js` |
| Content Extraction | 70% | Python + Ollama VLM | في `mini-services/control-center/content-extractor/` |
| Video Rendering | 60% | Remotion 4 + FFmpeg | prototype يعمل (درس ohm-law فقط) |
| AI Content Generation | 10% | LM Studio + Ollama | سكربتات أولية فقط |
| Bidirectional Sync | 0% | — | لم يُبنَ بعد |

| DB Snapshot | قبل كل مرحلة | `db/custom.db` | نسخ الملف وإعادة تسميته |
| Factory Code | نهاية كل يوم | `mini-services/control-center/` | `git commit` |
| Platform Code | نهاية كل يوم | `src/`, `prisma/`, `public/` | `git commit` |
| Generated Content | بعد كل batch | `data/books/*/` | Git LFS أو نسخ يدوي |
| Config Files | قبل أي تغيير | `data/config/` | `git commit` |

### 6.2 سيناريوهات التراجع

#### السيناريو أ: فشل المرحلة 2 (PDF Pipeline)

```
السبب المحتمل: Ollama VLM لا يعمل، أو VRAM غير كافٍ
الإجراء:
  1. التراجع لآخر DB snapshot سليم
  2. إذا Ollama لا يعمل:
     - تثبيت إصدار أقدم
     - استخدام نموذج أصغر (gemma3:4b)
  3. إذا VRAM غير كافٍ:
     - تقليل max_size من 512 إلى 384
     - زيادة cooldown من 10 إلى 20 ثانية
  4. الخيار الأخير: استخراج يدوي (copy-paste من PDF)
```

#### السيناريو ب: فشل المرحلة 3 (AI Content Generation)

```
السبب المحتمل: LM Studio لا يستجيب، أو المحتوى رديء
الإجراء:
  1. التراجع لآخر DB snapshot سليم
  2. إذا LM Studio لا يعمل:
     - الانتقال لـ Ollama (qwen2.5:7b)
     - تحديث model-router.ts لاستخدام Ollama
  3. إذا المحتوى رديء:
     - ضبط temperature (أقل = أكثر دقة)
     - تحسين prompt templates
     - استخدام Scaled Oss 36B بدلاً من 7B
  4. الخيار الأخير: كتابة المحتوى يدوياً في الـ Dashboard
```

#### السيناريو ج: فشل المرحلة 5 (Video Factory)

```
السبب المحتمل: Remotion crash، أو FFmpeg لا يعمل، أو Chrome OOM
الإجراء:
  1. التراجع لآخر DB snapshot (المحتوى النصي والمرئي محفوظ)
  2. إذا Remotion crash:
     - تقليل concurrency إلى 2
     - تقليل resolution إلى 720p
     - تحديث Chrome/Chromium
  3. إذا FFmpeg لا يعمل:
     - إعادة تثبيت FFmpeg
     - استخدام preset "superfast" بدلاً من "fast"
  4. الخيار الأخير: تصدير المحتوى بدون فيديو
     - المنصة تعرض المحتوى النصي + المرئيات بدون فيديو
```

#### السيناريو د: تلف قاعدة البيانات

```
السبب المحتمل: crash أثناء كتابة، أو disk full
الإجراء:
  1. إيقاف كل الخدمات فوراً
  2. نسخ DB التالف لـ `custom.db.corrupted`
  3. استعادة من آخر snapshot:
     cp custom.db.backup.2025-07-XX custom.db
  4. فحص السلامة:
     sqlite3 custom.db "PRAGMA integrity_check;"
  5. إعادة التشغيل والتحقق
  6. إعادة تشغيل آخر batch فاشل
```

### 6.3 نقاط عدم الرجوع (Points of No Return)

| النقطة | المهمة | السبب | التخفيف |
|--------|--------|-------|---------|
| بعد P1-021 | ربط Factory بـ Platform DB | تغيير Schema يؤثر على المنصة | DB snapshot قبل البدء |
| بعد P2-062 | كتابة extracted content في DB | بيانات كثيرة تُكتب | يمكن حذف Lessons وإعادة الاستخراج |
| بعد P3-060 | توليد محتوى AI دفعي | محتوى كثير يُولد | يمكن حذف وإعادة التوليد |
| بعد P5-051 | تحديث videoUrl في Platform | تغيير رابط الفيديو | يمكن nullify videoUrl |

> **ملاحظة**: لا يوجد نقطة عدم رجوع حقيقية لأن كل شيء محفوظ في Git و SQLite (يمكن حذف وإعادة). الخطر الوحيد هو تلف DB، ولذلك النسخ الاحتياطي إلزامي.
